# 2.0：钢笔绘制与单字轮廓编辑

本地试排工具增加两个入口，共用真实轮廓编辑器：顶部“钢笔绘制”从空白开始，网格单字的放大窗“编辑轮廓”载入已有字形。手改针对字形，导出后该字形在整套字体中生效；不等于只改某个单词中的一次显示。

## 启动与源文件

先用现有含 fontTools 的 Python 生成本轮试排包：

```bash
python /absolute/path/to/hunter-font-design/scripts/create_proof.py /project/fonts/Family.ttf /project/proof-v002
```

普通试排仍可离线直接打开 `index.html`。实际读取/回写轮廓需要本地 Python 服务：macOS 双击随包的 `打开字体编辑器.command`，或运行：

```bash
python /project/proof-v002/editor-runtime/serve_editor.py /project/proof-v002 --open
```

从离线试排页或静态预览点编辑时，页面会提示使用本机启动器。已有字形编辑到一半遇到连接中断，可以先保存 JSON 源稿，再用启动器打开并载入。

启动器使用生成包时的 Python 环境；该环境移动或删除后，改用已安装 fontTools 的 Python 执行上面的命令。编辑与字体导出在本机处理；服务只监听 `127.0.0.1`，不覆盖原字体。用户明确点击“交给 Codex”时，另按下节保存接续包并投递对话消息。关闭启动终端会停止服务，之后可再次启动。

直接使用共享模板时，运行 skill 的 `scripts/serve_editor.py /absolute/path/to/assets/proof-tool --open`。载入本地字体后编辑；未载入字体也可从“钢笔绘制”建立最小空白 TTF。新空白字体只是绘制母版：默认 1000 UPM、基线 0、大写线 700、小写线 500、上伸 800、下伸 -200；项目需采用其他母版参数时应从对应项目字体开始，不把此初始数值当成所有字体的设计标准。名称与许可未确认前不作为正式发行字体。

## 绘制和精修

1. 选一个字符，点击“载入字形”或“从空白绘制”。载入的是字体的真实轮廓，不从 Canvas 字框反推，也不描浏览器回退字。未收录字符可新增。
2. 钢笔 `P`：单击落点形成直线；按住拖出方向柄形成三次贝塞尔；点起点或在画布按 Enter 闭合。闭合后继续落点建立另一轮廓。外轮廓与内腔按 nonzero 规则填充，需要时选择节点后“反转轮廓方向”。未闭合轮廓不能暂存或导出。
3. 选择 `V`：拖锚点或控制柄；侧栏精确输入 X/Y；方向键移动 1 u，Shift 移动 10 u。锚点移动带动相邻控制柄，闭合起点两侧一起移动；手柄单独移动。可用节点下拉框和数值输入进行键盘编辑。
4. 双击线段插入点，使用贝塞尔分割保留曲线形状；删除锚点、直线/曲线转换会改变轮廓，应观察实际效果。支持删除整个轮廓、撤销/重做、占位宽度、网格吸附、原字对照、填充层、缩放和空格拖动画布。
5. 可载入本地 PNG/JPG/WebP 作参考底图，调 X、顶部 Y、宽度和透明度；底图保留比例、不自动描摹。参考图是绘制依据，不证明字形覆盖、来源权利或制作精度。底图随 JSON 保存，仅矢量轮廓写入字体与 SVG。
6. “字形透明度”以 0–100% 独立调节黑色填充，保留可见的轮廓线、锚点和手柄；与参考底图透明度分开。它仅影响编辑时的对照显示，不改变源稿轮廓、SVG 或字体的填充。

编辑坐标使用**原字体 UPM，Y 轴向上**；既有网格校样仍用归一的 1000 u。两者有明确单位标记，不能直接把一个界面的读数当成另一个界面的原始坐标。新建轮廓的点击/拖动按整数单位落点，已有轮廓及数值输入保留小数。

## 保存、重开与真实导出

- “暂存此字”把当前字形加入本次源稿，可从“源稿”区的“暂存字形”列表选择以继续修改；列表与数量说明其位于当前页面内存，不等于已保存文件。刷新或关闭页面前，使用顶部“保存源稿”或侧栏“保存 JSON 源稿”；文件位置由浏览器下载设置决定。有未暂存修改时切换/关闭须明确放弃；有未保存内容时提示页面离开。更新程序时不得直接刷新用户含未保存修改的页面，先由用户保存源稿，或通过可用界面完成保存并核实文件。
- JSON 保存原字体 SHA-256、UPM、码点与字形名、占位宽度和 M/L/Q/C/Z 路径，并内嵌原字体及参考图。重开源稿时校验字体哈希；需要时恢复内嵌原字体。不得删除内嵌底字的权利归属或把源稿作为无权分发的字体包公开发布。
- “导出新字体”把暂存的修改及当前字形一起写入新的整套字体文件；关闭编辑器可直接试排新稿，下载后可安装到系统供设计软件使用。JSON 源稿用于继续编辑，不是可安装字体；单字 SVG 用于矢量排版，也不代替字体文件。只下载审校副本，原文件和上游参数脚本/UFO/Glyphs 不被覆盖。保存 JSON 可保留本轮导出报告。
- 源稿是可重复的手改补丁。重建原字体后，在其**同哈希版本**上应用；上游源改变则先重新加载并核对旧修改，不能放宽哈希检查直接套用。命令行可重放源稿，目标文件必须不存在且保留原容器扩展名：

```bash
python /absolute/path/to/hunter-font-design/scripts/glyph_editor.py /project/fonts/Family.ttf /project/edits.json /project/fonts/Family-edited.ttf
```

## 把手改字形交给 Codex

点击顶部“交给 Codex”，可在侧栏填写“接下来怎么改”，再点“发送到 Codex”。当前字形与已暂存字形一起处理：先在试排目录的 `codex-handoffs/return-…/` 新建接续包，保存原字体、含原字体的节点 JSON、修改后字体、逐字 SVG、请求文字与文件哈希。**真实 JSON 节点是接续输入；截图只作辅助，不从截图重新描字。** Codex 收到消息后先读清单、核对哈希与手改结果，再按用户填写的要求修改；没有后续要求时只核验并确认接收，不自行扩字。

2.0.3 的默认路径直接投递到绑定的本地 Codex 桌面对话，不依赖剪贴板或组件宿主桥。生成器将创建该试排包时的 `CODEX_THREAD_ID` 与已安装 Codex 命令位置保存到 `codex-target.json`；服务器也可在从 Codex 启动时读取当前环境。发送目标由服务器配置，浏览器请求不能更换对话。实际调用为 `codex queue --thread <UUID> --message <接续消息>`，使用参数数组执行，不拼接 shell，不增加模型或审批选项。使用前确认已安装 CLI 的 `queue --help` 支持该命令。

区分“源稿已保存”“已投递到对话队列”和“Codex 已接收”：命令成功后显示入队状态并保存队列 ID，不能报成模型已读或已完成修改。桌面客户端正在回复时，在本轮结束后接续处理；客户端退出或目标对话未打开的自动处理不在本轮验证范围。进程失败或超时仍保留接续包；超时只报发送状态未确认，不自动重试。页面抑制同一份修改和要求的重复投递，失败时提供备用接续消息。`delivery.json` 留存真实投递结果。

只在用户点击“发送到 Codex”时投递，不因暂存、普通导出或准备包自动发消息。新页面使用 `/api/handoff/send`；旧 `/api/handoff` 继续只准备接续包，防止旧页面自动复制后又隐式发送导致重复。不要附加 `--resume`，也不启动额外 daemon 或模型进程争抢桌面对话的 active writer。入队与唤醒是两个步骤，不能把唤醒失败等同于入队失败。旧页面更新前仍先保存 JSON，确认下载后再刷新、载入。联调消息须明确标注测试字形，不冒充用户实际手改。

## 回写范围和必需复查

支持静态 glyf TTF、普通 CFF OTF，以及对应的 WOFF/WOFF2 容器；WOFF2 需已有 Brotli。三次曲线写入 TrueType 时按最多 0.5 个原字体单位的误差转换为二次曲线；已有二次曲线保持二次描述，不把所有字形转成三次。依据 [FontTools Cu2QuPen](https://fonttools.readthedocs.io/en/latest/pens/cu2quPen.html) 和 [TTGlyphPen](https://fonttools.readthedocs.io/en/latest/pens/ttGlyphPen.html)。

仅替换修改字形的轮廓与占位数据，新增字符时补 cmap 与必要的 glyph order。原有 GPOS/GSUB、名称和权利字段保留；版本及唯一 ID 标成新的编辑审校稿。轮廓变更使修改字形的旧 hinting 无效，不能将新节点序列配旧指令；原有设备度量缓存和签名按报告移除，须重新验收屏显。

复合字形被编辑时展开为独立轮廓；修改其部件时仍会影响关联的复合字形，报告列出关联范围并清除关联字形的旧指令。多个码点共用同一 glyph 时修改会一起生效。依赖节点编号连接的复合字形暂不回写，避免改变节点序列后错误连接。参考 [FontTools glyf](https://fonttools.readthedocs.io/en/latest/ttLib/tables/_g_l_y_f.html)。

本版不回写可变、CFF2、CID CFF、彩色/位图字体，不提供整词专用字标布局、组件编辑、布尔运算、字偶或附标锚点面板。用户要求这些能力时应按专项流程回源处理，不能以静态默认实例或黑色轮廓覆盖原字体功能。字体 hinting、OpenType 附标锚点与编辑画布的轮廓锚点是不同数据。

每轮手改后：回读实际导出、对比修改字形及关联字形，核对其他轮廓/度量/布局与权利资料；重新生成同哈希试排和必要样张，执行第 3.5 节光学及字距审校。源稿能保存或浏览器能显示都不等于正式发行通过。
