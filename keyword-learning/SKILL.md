# Keyword Learning

## Purpose

关键词学习法把关键词视为知识节点，把关键词之间的关系视为连接，把学习过程视为一张持续更新的知识图谱。

目标不是收集术语，而是帮助学习者形成一个能够解释、推理、应用和继续扩展的 Mental Model：

**Finish-line Task -> Learner Model -> Orientation -> Expansion -> Compression -> Deep Practice -> Retrieval & Transfer -> Updated Map**

即：

**终点任务 -> 学习者模型 -> 快速定向 -> 由薄到厚 -> 由厚到薄 -> 深度练习 -> 提取迁移 -> 更新地图**

“快速入门”不是尽快把名词念完，而是尽快获得三个能力：能用一条因果主线说明领域、能读懂专业资料的关键词、能完成一个最小真实任务。答案必须同时留下可继续扩展的全景地图。

## Two Independent Budgets

不要用“控制认知负荷”作为减少领域覆盖的理由，也不要用“内容丰富”作为一次解释所有词的理由。始终把宽度和深度分开控制：

- **宽度预算**：首轮先发现足够多的相关关键词，并分组展示全景。
- **深度预算**：每轮只深入少数关键词，但每个词必须解释到机制、边界和应用。

默认参考范围：

| 输出层 | 作用 | 默认规模 |
|---|---|---:|
| 快速定向 | 先得到可用的最小心智模型 | 1 条领域故事、5-9 个骨架节点、1 个贯穿案例 |
| 全景词库 | 防止遗漏重要板块 | 窄概念 25-50 个词；宽领域 60-120 个词，必要时 80-150 个；8-16 个主题簇 |
| 基石关键词 | 构成领域骨架 | 12-20 个词 |
| 本轮深挖 | 建立真正理解 | 3-5 个词 |
| 下一轮队列 | 保持学习方向 | 3-7 个词 |

范围用于保证覆盖，不用于机械凑数。窄概念可以少一些，大型领域可以更多；无关词进入 Parking Lot，而不是填充正文。

## Method Foundations

借鉴方法只转化为动作，不用名人名词装饰答案，也不把任何单一流派当成普遍真理：

| 方法启发 | 在本 Skill 中的动作 |
|---|---|
| 华罗庚“由薄到厚、由厚到薄” | 先给极简骨架，再扩成宽图谱，最后压缩成学习者自己的领域模型与判断清单。压缩不是删词，而是说明哪些关系统摄了大量细节。 |
| 陶行知“教学做合一” | 先定义一个最小真实任务；知识必须进入观察、操作、判断或作品，不能停在听讲。 |
| 叶圣陶“教是为了不教” | 支架逐轮渐隐：完整示范 -> 补全关键步骤 -> 独立完成 -> 新情境迁移，最终让学习者能自己扩图、查证和纠错。 |
| Ausubel 的先备知识与先行组织 | 先探测已有模型和误解，再用领域故事、上位概念和骨架关系挂接新知识。 |
| Bruner 的螺旋式学习 | 反复回到同一批核心节点，每轮增加机制、度量、边界、应用或争议，而不是每轮只换新词。 |
| Bloom 的掌握学习 | 明确可观察的掌握标准，短测诊断后只做针对性纠正，再测一次。 |
| Ericsson 的刻意练习 | 把真实任务拆成可观察子技能，选择当前最弱的一项，给清晰目标、即时反馈和下一次尝试。重复时必须针对错误改变动作。 |
| Chi / Renkl 的自我解释与样例渐隐 | 新手先看带理由的完整 worked example，并解释每一步为什么；随后逐步拿掉步骤，过渡到独立解决。 |
| Roediger、Karpicke 与 Bjork 的提取、间隔和交错 | 少重读，多闭卷重建；跨轮回访旧节点，并交错比较易混概念。主观流畅不等于长期掌握。 |
| 费曼式通俗重述 | 要求不用术语堆叠向外行讲清楚；卡住处就是待补节点。通俗表达仍须接受机制、边界和证据检查。 |
| 变式与对比学习 | 用正例、非例、边界例和最近邻概念改变单一条件，迫使学习者识别决定性特征。 |

保留概念图、先修依赖图和阈限概念作为组织工具：概念图负责关系，依赖图负责顺序，阈限概念负责寻找一旦理解就会重组全局的知识枢纽。

## Core Principles

### 1. 关系命题才是知识

关键词只是节点。知识必须写成可以判断真假的关系命题：

**A --[关系动词]--> B：为什么成立、在什么条件下成立。**

避免只画没有连接语的树，也避免把并列出现误当作真实关系。

### 2. 先薄后厚，再厚后薄

默认顺序：

**领域故事与骨架 -> 全景扫描 -> 聚类 -> 基石词 -> 先修闭包 -> 深挖 -> 压缩重建 -> 应用**

第一层“薄”让初学者先知道自己身处哪里；“厚”负责补足领域覆盖和真实复杂性；最后一层“薄”把大量细节压成少数可生成、可预测、可行动的关系。不要一上来倾倒词表，也不要把最初的简化模型误当成全貌。

### 3. 深度必须达到机制与边界

定义、比喻和例子只能建立初步认识。核心词至少回答：

1. 它是什么；
2. 它为什么出现、解决什么问题；
3. 它如何运作，关键步骤和因果链是什么；
4. 它依赖什么、影响什么；
5. 它不是什么，何时失效或不适用；
6. 如何观察、衡量或验证；
7. 如何用于真实情境；
8. 学习者能否在新情境中迁移。

### 4. 学习路径由目标和依赖共同决定

不要按字母、热度或百科目录排序。优先级同时考虑：

**学习价值 ~= 目标相关性 × 领域中心性 × 先修价值 × 迁移价值 × 当前缺口 / 学习成本**

不机械计算分数；用它解释为什么现在学这个词。

### 5. 区分事实、模型、经验规则和争议

明确标注：

- **广泛共识**：有稳定定义或证据支持；
- **解释模型**：帮助理解，但不是事物本身；
- **经验规则**：在一定条件下有用；
- **流派观点**：来自特定理论或实践传统；
- **未决争议**：存在合理分歧；
- **前沿假设**：证据仍在发展。

### 6. 掌握必须留下证据

“已经读过”“感觉理解”不能把节点标记为掌握。至少要通过一次主动解释、关系重建、案例判断或迁移任务。

### 7. 从终点任务倒推，而不是从目录顺序出发

把“入门 X”改写成可观察的终点，例如“能看懂一篇行业报告并指出三项关键变量”“能画出系统能量流并定位常见故障”“能独立完成一个最小作品并解释取舍”。地图、深挖和练习都服务于这个终点；与终点无关但值得保留的词进入 Parking Lot。

### 8. 示例先完整，支架后渐隐

对新手，不直接扔一道无提示综合题。默认练习阶梯是：

**完整示范 -> 解释示范 -> 补全一步 -> 独立同构题 -> 变式题 -> 真实任务**

如果学习者已经能独立完成，则跳过示范，直接用迁移题定位薄弱处。不要让熟练者继续被低价值支架拖慢。

### 9. 内容丰富度由覆盖结构决定，不由字数决定

一份合格地图同时回答：领域里有什么、如何运转、如何判断、如何行动、如何验证、何时失败、如何演化。每个主题簇除关键词外，至少给出它回答的问题和一条关键关系；重要技术词首次出现时附常用英文名或缩写，帮助后续检索。

### 10. 一次回答也要形成闭环

用户可能不回复测试题。首轮不能把关键教学价值押在下一轮：必须先给一个示范性自测过程或带答案的校准例，再给 2-4 道不立即揭示答案的输出题。没有学习者回答时，只能报告“材料已交付、掌握未验证”，不能把测试题数量当成完成证据。

## Operating Modes

根据用户请求选择模式，不必每次都执行完整课程。

| 用户意图 | 默认模式 | 主要输出 |
|---|---|---|
| “我完全不懂 X，快速入门” | Rapid Entry | 领域故事、骨架图、贯穿案例、检索词、首个真实任务，再附扩展地图 |
| “什么是 X？” | Concept Panorama，默认 L2 | 锚点定义、全景词库、基石路径、3-5 个深挖、关系图、测试 |
| “给我关键词地图” | Atlas | 主题簇、窄概念 25-50 词或宽领域 60-120 词、多视图关系、覆盖审计 |
| “彻底理解 X” | Deep Dive | 先修闭包、机制链、边界、对比、证据、迁移 |
| “X 和 Y 有什么不同” | Compare | 共同上位概念、对比轴、机制差异、选择条件、共存关系 |
| “系统学习 X” | Curriculum | 全景、依赖路径、分轮计划、掌握状态、复习队列 |
| “找知识盲区” | Blind Spot Audit | 缺失板块、隐含前置、反例、争议、Unknown Queue |
| “检查我是否理解” | Output Test | 闭卷解释、关系重建、反例、迁移任务与诊断 |

如果用户只给一个宽主题，默认采用 Rapid Entry + L2：先用一小段完成定向，再展开足够宽的地图和第一轮深挖。默认学习者为聪明的零基础成年人，目标是“能解释领域主线、读懂基础资料、完成一个最小真实判断或任务”。显式说明该假设，但不因可合理推断的信息而停下来追问。

## Workflow

### Phase 1: Set the Focus Question

把宽泛主题改写成一个本轮要回答的焦点问题，例如：

- “什么是股票？” -> “股票如何把公司所有权、融资和市场定价连接起来？”
- “什么是光模块？” -> “光模块如何在网络设备与光纤之间完成高速信号转换？”

确定或推断：

1. 学习主题；
2. 使用场景；
3. 目标深度；
4. 已知基础；
5. 可用时间或篇幅；
6. 最终输出或任务；
7. 成功时可以观察到的行为。

用一行 **Learning Contract** 表达：

> 面向[学习者基础]，为了[真实场景]，在[时间/篇幅]内达到[深度]，最终能够[可观察任务]；当前先按[关键假设]推进。

只有缺失信息会实质改变路线时才提问，最多问 1-3 个高信息量问题。用户没回答时，带着显式假设继续，不阻塞首轮输出。

可选入口诊断只取最小样本：让学习者尝试一句定义、画一条因果链、判断一个边界例，并分别报 0-100% 信心。诊断用于改变学习路线，不用于评分羞辱；没有回答则将节点暂记 U0/U1，不臆测掌握。

### Phase 2: Give a Thin Orientation

在宽图谱之前先给一个能立刻使用的先行组织，控制在一小段或一张紧凑图：

1. **领域故事**：`现实问题 -> 核心对象 -> 关键机制 -> 结果/价值 -> 反馈/约束`；
2. **5-9 节点骨架**：节点间必须使用带动词的关系；
3. **贯穿案例**：选一个典型对象或事件，后文所有抽象概念尽量回扣它；
4. **三条边界**：这个领域不是什么、不能解决什么、与最近邻领域如何分工；
5. **路标词**：给出 8-15 个中英双语检索词，让学习者能继续查资料。

这一阶段允许简化，但要明确简化遗漏了什么，并承诺在全景或深挖阶段补回。

### Phase 3: Build a Broad Keyword Atlas

先选择最匹配的 **Domain Lens**，再从通用雷达中扫描。不要把工程领域教成名词百科，也不要把人文领域硬套成机器流程。

| 领域镜头 | 默认追问 |
|---|---|
| 自然科学 | 对象与尺度是什么？受哪些定律/守恒/相互作用支配？如何实验、测量、证伪？ |
| 工程与技术 | 需求是什么？架构、接口和关键流是什么？瓶颈、权衡、故障模式和验证方法是什么？ |
| 产业与商业 | 价值链、客户、供需、成本/利润池、竞争壁垒、周期、监管和关键指标是什么？ |
| 医疗与生命 | 正常机制、病理变化、风险因素、诊断证据、干预、预后和不确定性是什么？ |
| 法律与政策 | 权利义务、主体、程序、管辖、证据标准、救济、例外与政策目标是什么？ |
| 历史与人文 | 时空背景、行动者、制度、观念、材料来源、因果解释、分期与争议是什么？ |
| 社会科学 | 个体/群体/制度处于什么层级？激励、权力、机制、变量、方法和替代解释是什么？ |
| 实践技能 | 成品标准、子技能、动作顺序、反馈信号、常见错误、训练环境和迁移任务是什么？ |

从下列雷达维度中选择至少 8 个与领域有关的维度进行扫描。宽领域通常使用 10-16 个；不适用的维度跳过，不要硬填。

| 雷达维度 | 要找什么 |
|---|---|
| 核心对象 | 领域在研究、操作或解释什么？ |
| 问题与需求 | 为什么会产生这个领域？要解决什么痛点？ |
| 基础原理 | 哪些规律使它成立？ |
| 构成与架构 | 系统由哪些部件、层级或角色组成？ |
| 机制与过程 | 输入如何经过步骤变成输出？ |
| 方法与策略 | 有哪些做法、模型或解法？ |
| 工具与基础设施 | 实践依赖哪些工具、平台或材料？ |
| 数据与表示 | 信息如何被记录、编码或组织？ |
| 指标与单位 | 如何衡量状态、质量、成本和效果？ |
| 分类与路线 | 有哪些类型、流派、技术路线或替代方案？ |
| 角色与激励 | 谁参与、谁受益、谁承担成本或风险？ |
| 标准与治理 | 哪些协议、法律、规范或伦理边界生效？ |
| 生命周期 | 从产生、使用到失效经历什么阶段？ |
| 历史演化 | 旧问题、旧方案、局限和新范式是什么？ |
| 失败与争议 | 常见故障、误区、反例和未决争论是什么？ |
| 场景与案例 | 真实世界在哪里使用或体现？ |
| 前沿方向 | 当前正在出现哪些新问题和新路线？ |

输出为按主题簇组织的 **Keyword Atlas**。宽领域默认 60-120 个词，必要时扩到 80-150 个；窄概念可用 25-50 个。关键词可以紧凑罗列，但每个簇必须包含：

- 它回答的领域问题；
- 5-12 个规范关键词，必要时含英文名、缩写、同义词和一词多义提示；
- 至少一条跨词关系命题；
- 一个初学者常漏掉的观察点。

地图至少同时出现六类知识：对象/分类、机制/因果、方法/动作、指标/证据、边界/失败、历史/争议。不能只收名词和产品名。

### Phase 4: Run a Coverage Audit

在筛选核心词之前检查：

1. 是否只有“名词”，缺少机制、指标、角色、风险或历史？
2. 是否偏向某一流派、地区、商业立场或时间阶段？
3. 是否遗漏专业人士默认知道、初学者却不知道的隐藏前置？
4. 是否包含概念的反例、替代方案和失败模式？
5. 是否把产品名、人物或实例误当成上位概念？
6. 是否存在多个同义词应当合并，或一个词其实包含多种含义应当拆分？
7. 是否能从地图读出一条端到端主线，而不只是看到分类？
8. 是否包含专业人士真正用于判断的指标、证据和工作产物？
9. 是否至少有一个贯穿案例、一个失败案例和一个边界案例？
10. 是否能用地图中的词构造用户的终点任务？不能则说明缺少程序性或条件性知识。

发现缺口后先补词，再进入筛选。

当主题宽、专业、冷门、动态或要求“深入研究”时，若工具可用，至少从以下四类材料交叉扩词和校正关系：

1. 教材目录、大学课程或专业能力框架，用于检查基础覆盖；
2. 官方标准、监管文件或专业协会词汇，用于规范术语和边界；
3. 原始论文、系统综述或权威手册，用于验证机制与争议；
4. 真实工作流、案例、故障/事故复盘或代表性数据，用于补方法、指标与失败模式。

检索的作用是纠偏和发现 Unknown Unknown，不是把引用数量当作深度。若无法检索，明确标记可能遗漏和待验证节点。

### Phase 5: Select and Classify Keystone Keywords

从全景词库中选择 12-20 个基石词，并标注角色：

| 角色 | 作用 |
|---|---|
| 入口词 Anchor | 用最少背景说明领域在谈什么 |
| 先修词 Prerequisite | 不理解它就无法理解后续节点 |
| 阈限词 Threshold | 理解后会重组对整个领域的看法 |
| 枢纽词 Hub | 与多个主题簇相连 |
| 桥接词 Bridge | 连接两个原本分离的板块 |
| 操作词 Operator | 表示关键方法、动作或过程 |
| 度量词 Measure | 让抽象概念可以观察和比较 |
| 边界词 Boundary | 揭示限制、反例、风险或替代方案 |

每个基石词说明：为什么重要、连接哪些簇、需要哪些前置、为什么现在学。

### Phase 6: Build Multiple Relationship Views

宽领域默认给出至少三种视图，其中必须包含依赖视图、机制/因果视图，以及决策/证据视图；窄概念至少两种。复杂领域可增加到 4-5 种。

1. **分类视图**：上位、下位、类型和实例；
2. **依赖视图**：理解 B 前必须先理解哪些 A；
3. **机制视图**：输入、状态变化、输出和反馈；
4. **因果视图**：什么导致、促进、限制或抑制什么；
5. **流程视图**：事件或操作按什么顺序发生；
6. **对比视图**：相似概念在哪些轴上不同；
7. **角色—激励视图**：谁做决定、谁承担成本、谁获得收益；
8. **演化视图**：Problem -> Old Solution -> Limitation -> New Keyword -> New Paradigm。
9. **决策视图**：面对什么信号，比较哪些变量，满足什么条件时选择哪条路径；
10. **证据视图**：主张由什么观测、实验、数据或材料支持，可能被什么证据推翻。

优先使用完整命题：

**A --[导致/依赖/包含/限制/替代/衡量]--> B：条件或原因。**

主动寻找跨主题连接。只有树状从属关系而没有横向连接，通常说明地图还不够成熟。

完成关系图后做一次 **厚到薄压缩**：用 8-15 条关系命题、一个端到端流程或一张判断清单重建整个领域。说明这些关系各自压缩了地图中的哪些细节；不能被压缩的例外保留为边界词。

### Phase 7: Close Prerequisite Gaps

在深挖一个关键词前，向上追踪它的先修闭包：

1. 这个词依赖哪些概念？
2. 学习者是否已经能解释这些概念？
3. 哪个缺失前置会阻塞当前理解？

只补充真正阻塞的 1-3 个前置微课，不因追溯先修而无限展开。隐藏前置补齐后返回原关键词。

### Phase 8: Deep Dive in Small Rounds

默认每轮深入 3-5 个关键词。每个核心词使用下面的 **Depth Ladder**；根据目标合并字段，但不得跳过机制、关系、边界和应用。

#### Depth Ladder

1. **准确识别**：一句话定义、必要特征、常见同义词；
2. **直觉模型**：用通俗语言、类比或可视化说明，但标出类比会在哪里失效；
3. **问题来源**：它为何出现，替代了什么旧方案或解释了什么现象；
4. **运行机制**：按 `输入 -> 关键状态/步骤 -> 输出 -> 反馈` 解释因果链；
5. **结构关系**：上位、下位、先修、协同、替代和跨簇连接；
6. **对比边界**：最近邻概念、非例、反例、适用条件和失败模式；
7. **度量证据**：如何观察、衡量或验证；证据是否稳定、有争议或会随时间变化；
8. **完整案例**：至少一个从条件到结果的 worked example，适合时加入数字、步骤或真实约束；
9. **迁移应用**：换一个新情境，判断它是否仍适用以及为什么；
10. **压缩表达**：学习者能否用自己的话重建这个词及其三条关键关系。

#### Mechanism Standard

解释机制时避免“它通过优化、协同、赋能实现效果”这类空转表达。必须尽量指出：

- 输入和初始条件；
- 参与的部件、角色或变量；
- 发生变化的中间状态；
- 决定结果的关键因果步骤；
- 输出、反馈和停止条件；
- 改变某个条件后结果会怎样。

#### Depth Gate

核心词讲解若不满足以下最低证据，不得称为“深入”：

- 至少一条不少于 3 个环节的因果链，并解释每一步为什么；
- 至少一个变量变化预测：`如果 X 增/减或条件 C 消失，Y 会怎样，为什么`；
- 至少一个完整 worked example，展示从条件、选择到结果，不只报结论；
- 至少一个最近邻对比、一个非例或反例、一个失败模式；
- 至少一个可观察指标、证据来源或验证动作；
- 至少一个面向终点任务的决策：何时用、何时不用、替代方案是什么；
- 最后用不依赖黑话的 3-5 句话压缩，并指出这个简化在哪会失效。

按领域追加，不机械套用：

- **定量/自然科学**：给变量、单位、数量级、必要公式或守恒关系，并写清假设；
- **工程/技术**：给端到端流、接口、瓶颈、权衡、故障信号和验证方法；
- **产业/商业**：给价值链位置、参与者激励、成本/收益驱动、周期和关键指标；
- **历史/人文/社会科学**：给时空语境、材料依据、行动者、机制性解释、竞争解释和反事实边界；
- **法律/医疗/金融等高风险领域**：给适用范围、证据等级、不确定性、例外和需要专业判断的边界；
- **实践技能**：给动作标准、示范、反馈信号、常见错误、修正练习和真实成品。

如果一段解释替换关键词后仍能适用于许多无关概念，说明它在使用“优化、赋能、协同、提升”等空词，必须重写为具体变量、动作和因果。

### Phase 9: Practice, Verify, Correct, and Update

每轮结束后：

1. 对 U0/U1 学习者给一个带理由的完整示范，并要求指出每一步连接了哪些概念；U2 及以上可直接从独立题或迁移题开始；
2. 拿掉一个关键步骤，让学习者补全；
3. 给同结构新题，要求独立完成；
4. 给改变表面特征或关键条件的迁移题；
5. 对答案分别记录正确性与信心，识别“不懂”“关系错”“会做但说不清”和“高信心误解”；
6. 根据错误类型只回补所需节点，然后用一道新题复测；
7. 更新 Domain Map、Relationship Views、Mastery、Unknown Queue 和 Review Queue；
8. 决定继续、回补先修、交错比较、进入真实任务或停止。

纠错必须对应根因：

| 错误类型 | 最小纠正动作 |
|---|---|
| 定义或边界混淆 | 正例 / 非例 / 边界例三联对比 |
| 先修缺口 | 1-3 个阻塞前置微课后返回原题 |
| 机制断链 | 重画输入、状态变化、输出、反馈，并追问缺失的 Why |
| 关系或层级错误 | 从空白重建 5-10 个节点和带动词连接 |
| 只会照例模仿 | 改变一个决定性条件做变式题 |
| 应用选择错误 | 对比两个方案的适用条件、代价和失败信号 |
| 高信心错误 | 立即给反例或可验证证据，再要求重新预测 |

不重复原解释冒充纠错；第二次尝试必须是新题或新情境。

## Keyword Card

为本轮深挖词建立卡片。不要为全景词库中的每个词填卡。

```markdown
### [关键词]

- 节点角色：[入口 / 先修 / 阈限 / 枢纽 / 桥接 / 操作 / 度量 / 边界]
- 掌握状态：[U0 陌生 / U1 识别 / U2 可解释 / U3 可应用 / U4 可迁移]
- 当前信心：[0-100%，仅用于校准，不代表掌握]
- 核心问题：理解这个词后能回答什么此前回答不了的问题？
- 准确定义：它是什么？必要特征是什么？
- 直觉模型：怎样通俗解释？类比在哪里失效？
- 问题来源：为什么需要它？旧方案有什么局限？
- 先修概念：理解它前必须知道什么？
- 运行机制：输入、步骤、状态变化、输出和反馈是什么？
- 结构关系：上位、下位及最重要的跨簇连接是什么？
- 对比与边界：最易混概念、非例、反例、适用条件和失败模式是什么？
- 度量与证据：如何观察、衡量或验证？事实是否稳定或有争议？
- 条件变化预测：改变哪个变量会导致什么结果？为什么？
- 完整案例：在一个具体情境中如何从条件走到结果？
- 练习阶梯：完整示范 -> 补全 -> 独立 -> 变式 -> 真实任务，当前在哪一步？
- 迁移问题：换一个新情境，它是否适用？
- 我的解释：不用资料如何重建它？
- 掌握证据：通过了哪项输出测试？
- 下一节点：理解后最值得学习什么？
```

## Learning Depth and Node Mastery

学习任务的目标深度与单个节点的掌握状态是两件事。

### Target Depth

| 深度 | 目标 | 需要覆盖 |
|---|---|---|
| L1 认知 | 听懂讨论 | 地图、定义、高频关系、基本边界 |
| L2 理解 | 完整解释 | 原理、机制、对比、案例、常见误区 |
| L3 应用 | 解决问题 | 方法、工具、指标、工作流、失败诊断、真实任务 |
| L4 专业 | 评估或创新 | 底层理论、原始证据、历史、争议、行业生态、前沿 |

### Node Mastery

| 状态 | 可观察证据 |
|---|---|
| U0 陌生 | 不能识别或解释 |
| U1 识别 | 知道大致含义和所在位置 |
| U2 可解释 | 能闭卷说明机制、至少三条关系、边界，并做条件变化预测 |
| U3 可应用 | 能独立解决一个典型问题、解释选择并检查结果 |
| U4 可迁移 | 能在表面不同的新情境中应用、评价或修正概念，且能指出模型失效处 |

只有满足对应证据时才升级状态。另记 0-100% 主观信心，用来发现校准偏差；信心绝不能替代输出证据。

## Output Tests

每轮至少使用两种不同层级的测试，其中至少一种需要主动生成答案而不是选择答案。

- **主动回忆**：不看资料解释关键词；
- **通俗教回**：面向不了解该领域的人，用 3-5 句话说明并主动标出自己的卡点；
- **关系重建**：从空白开始重画 5-10 个节点及连接语；
- **Why/How 链**：连续解释三个因果步骤；
- **预测测试**：只改变一个条件，先预测结果和信心，再看证据；
- **A vs B**：比较最近邻概念并给出选择条件；
- **反例测试**：举出看似符合、实际不符合的例子；
- **故障诊断**：根据失败现象定位哪个机制或条件出问题；
- **迁移测试**：把概念应用到未讲过的新案例；
- **真实输出**：写文章、做讲解、完成分析、设计方案或解决项目问题。

首轮至少展示一次“题目 -> 学习者常见错误 -> 专家如何沿机制诊断 -> 修正答案”的校准示范，避免用户只收到一组尚未作答的问题。正式输出题不要紧接着给答案。

答案错误时，不只给正确答案；判断错误来自定义、先修、机制、关系、边界还是选择策略，然后回补对应节点并换题复测。

长期学习时，把已掌握节点放入复习队列，在出现适度遗忘后重新提取；把相邻、易混和可替代概念交错比较。复习间隔根据错误和目标调整：答错或高信心误解更早回访，稳定迁移成功则拉长；不要机械承诺固定日期，除非用户要求建立日程。

## Unknown Unknown Discovery

在全景建立后和每个主要阶段后执行 Blind Spot Scan：

1. 当前地图缺少哪些雷达维度？
2. 哪些阈限概念会改变整个理解框架？
3. 哪些低频词其实是隐藏前置？
4. 哪些指标决定专业人士如何判断好坏？
5. 哪些反例、失败模式和极端条件尚未覆盖？
6. 哪些角色、激励、标准或制度被忽略？
7. 当前地图是否把一种流派误写成整个领域？
8. 哪些旧概念已经被新范式替代，但仍在特定条件下有效？

每次只把 3-7 个高价值节点放入 Unknown Queue，并说明发现原因、阻塞的问题和推荐动作。其余进入 Parking Lot。

## Evidence and Research

普通稳定概念可直接解释。遇到动态前沿、专业争议、冷门主题或医疗、法律、金融等高风险内容时，先检索可靠资料。

优先级：

1. 原始论文、官方标准、法律法规、监管或机构文档；
2. 权威教材、系统综述或专业组织；
3. 高质量二手解释；
4. 社区经验仅用于发现案例或争议，不单独支撑关键事实。

研究不是为了堆参考资料，而是为了：补全关键词、验证关系、识别争议、纠正时间敏感信息。明确区分来源事实和自己的推断。

## Default Response for “什么是 X？”

默认 L2，输出顺序：

1. Learning Contract：推断的基础、场景、终点任务、深度和关键假设；
2. 快速定向：一句锚点定义、一条领域故事、5-9 节点骨架和一个贯穿案例；
3. 按 Domain Lens 建立全景词库：窄概念 25-50 词，宽领域 60-120 词，必要时 80-150 词；8-16 个主题簇；
4. Coverage Audit：补机制、指标、证据、方法、边界、失败、历史和隐藏前置；
5. 12-20 个基石词，按依赖顺序标注角色与“为什么现在学”；
6. 至少三种关系视图：依赖、机制/因果、决策/证据；窄概念可减为两种；
7. 厚到薄压缩：8-15 条可生成全局的关系命题、端到端流程或判断清单；
8. 本轮深挖 3-5 个词，通过 Depth Gate；
9. 一个完整示范和一段渐隐练习，再给至少两道闭卷输出题，其中一道是迁移、预测或反例；
10. 学习状态与信心校准、下一轮 3-7 个词、Unknown Queue、Review Queue 和 Parking Lot。

不要把全景词库的每个词都展开。快速定向保证能立即开始，宽图保证丰富度，Depth Gate 保证理解度，厚到薄压缩保证能带走并继续自学。

如果用户已经指定模式、节点或输出长度，直接进入对应模式，不重复完整开场。

## Persistent Learning Workspace

普通对话不创建文件。只有用户希望跨轮维护、导出或长期学习时，才使用：

```bash
python3 scripts/init_learning_workspace.py "学习主题" \
  --goal "学习目标" \
  --depth L2 \
  --output learning.md
```

脚本创建包含 Learning Contract、入口诊断、Thin Orientation、Domain Lens、Keyword Atlas、Coverage Audit、Keystone Keywords、Relationship Views、Deep-Dive Cards、Practice Ladder、Unknown Queue、Review Queue、Parking Lot、Output Tests 和 Round Log 的 Markdown 工作区。目标文件已存在时停止，不覆盖用户内容。

## Stop Rule

停止深入某个词的条件：

1. 已达到目标所需的 U 级别；
2. 能解释它为什么重要、如何运作以及何时不适用；
3. 能把它放回至少两条关键关系；
4. 通过与目标匹配的应用或迁移测试；
5. 继续深入的边际价值明显下降。

若目标是“快速入门”，还必须能完成三项退出任务：闭卷讲出领域主线；拿到一份新资料时知道关键词属于地图哪里；完成一个此前未演示的最小判断或操作。否则只是内容交付，不是入门完成。

整个学习任务在焦点问题和最终任务得到解决时结束，而不是在“列完所有词”时结束。结束时说明当前掌握、当前边界、尚未解决的 Unknown Queue、Parking Lot，以及自然的下一阶段。

## Rules

1. 禁止用少量基石词冒充完整领域地图。
2. 禁止用大量术语冒充内容丰富；关键词必须被聚类、分层或连接。
3. 禁止用定义和比喻冒充深入理解；核心词必须解释机制和边界。
4. 禁止无连接语的关系图；每条关键边都应形成完整命题。
5. 禁止一次深入所有词；宽地图与窄深挖必须并存。
6. 禁止跳过隐藏先修；只回补真正阻塞理解的节点。
7. 禁止把实例、产品名和人物默认当作上位概念。
8. 禁止把特定流派、地区或时代观点写成唯一答案。
9. 禁止只用熟悉感判断掌握；状态必须对应可观察输出。
10. 禁止虚构确定性；动态、争议和证据不足处必须标注。
11. 不为填满模板添加无关内容；字段服务于焦点问题。
12. 每轮更新地图、关系、掌握状态和下一步，而不是重复第一版答案。
13. 禁止所有领域都套同一张名词雷达；先选 Domain Lens，再补该领域特有的证据、指标和失败模式。
14. 禁止只出题不教学，或只给答案不让学习者生成；首轮至少有一个诊断示范，后续使用支架渐隐。
15. 禁止把流畅、篇幅、关键词数量或用户未反驳当作掌握；必须区分材料覆盖、当前表现与长期保持。
16. 禁止每轮只增加新节点；必须回到核心节点做更深机制、预测、比较或应用，形成螺旋上升。

## Command Patterns

- “用关键词学习法带我入门【X】，先给完整全景，再深挖第一组。”
- “我对【X】完全陌生，先用领域故事和贯穿案例让我快速定向，再给 80-120 词地图。”
- “给我建立【X】的 60 个关键词地图，按主题簇和依赖关系组织。”
- “找出理解【X】最重要的基石词、阈限词和隐藏前置。”
- “用 Depth Ladder 彻底拆解【X】。”
- “比较【X】和【Y】的机制、边界、适用条件和共同上位概念。”

## Master Prompt

执行本 Skill 时，把用户想学习的主题建模为由关键词节点、带语义的关系边、先修依赖和掌握状态构成的动态知识图谱。

先从用户想完成的真实任务倒推 Learning Contract，探测或合理推断先备知识。面对零基础用户先给“薄”的先行组织：领域故事、5-9 节点骨架、贯穿案例和边界，让用户立刻有路标；再选择合适的 Domain Lens，通过多维雷达把地图读“厚”。宽领域默认覆盖 60-120 个分组关键词，必要时 80-150 个；窄概念 25-50 个。地图必须同时有对象、机制、方法、指标、证据、失败和演化，且每个簇说明问题、关键关系和初学者盲点。

完成 Coverage Audit 后，筛选入口词、先修词、阈限词、枢纽词、桥接词、操作词、度量词和边界词，并按依赖安排路径。然后把厚地图重新压成 8-15 条能生成全局的关系命题、端到端流程或判断清单，说明哪些细节被压缩、哪些例外不能省。

宽度与深度独立控制：地图可以宽，每轮只深挖 3-5 个节点。深挖必须通过 Depth Gate：三步以上因果链、条件变化预测、完整样例、对比/反例、指标/证据、失败模式、真实决策和带失效边界的通俗压缩；再按领域补公式与单位、接口与权衡、激励与经济性、材料与竞争解释或专业风险边界。

宽领域至少建立依赖、机制/因果、决策/证据三种视图，并使用带动词的连接语形成完整命题。用完整示范 -> 解释 -> 补全 -> 独立同构题 -> 变式题 -> 真实任务逐步撤掉支架；通过主动回忆、关系重建、预测、反例、故障诊断和新情境迁移验证掌握。分别记录表现与信心，根据错误根因只回补必要节点并换题复测。

每轮更新地图、掌握状态、Unknown Queue、Review Queue 和 Parking Lot。用户没有回答测试时，只能说材料已交付、掌握未验证。任务在学习者能闭卷讲出主线、把新资料挂回地图、解决一个未演示的目标任务并知道模型何时失效时结束。
