# 喵掌勺封面：核心先排好，再延展

适用于视频完成后的封面，也适用于用户只要求封面的任务。先读取现行`video-cover-design`，本文件只补充本品牌的资产、中央安全区和已验证的生产顺序。

## 内容与素材

- 从真实视频取少量关键帧，分别说明主角身份、菜品、环境与搞笑表情；不要用泛化猫脸替换实际主角。
- 使用`assets/miao-zhang-shao-logo.png`作为本系列默认品牌资产，保留透明通道，先查看原图。它是既有logo，不是新logo设计任务；用户提供新版时以新版为准。
- 主标题默认只用菜名，不擅自加宣传语、期数、英文、平台UI或播放按钮。logo自身字样保留。
- 用内置图像生成工具把画面与中文一起完成；不是先用代码制作字牌海报。裁切与缩略预览可以用本地工具。

## 为什么先做3:4核心

直接生成9:16时，即使提示了安全区，模型仍可能把logo顶到画面顶部、把标题挤到底部。漂亮的全图不能证明裁切安全。本系列默认先做独立完整的3:4核心，再扩图；不必先重试几版失败的整幅布局。

### 3:4核心

按1080×1440理解构图，不把这些数值当成所有模型强制像素：

- Logo位于上部中央，和顶边、猫耳留呼吸间距。
- 白猫、黑猫的完整耳朵、脸与关键动作在中间；黑猫可用夸张表情表达本集笑点。
- 菜品在前景有食欲，和人物通过木勺、爪子或视线建立关系。
- 标题大、清楚，字形及描边阴影完整留在底边以内，不能贴边。
- 必须让logo、猫脸、主要菜品和全部文字共同装进这张核心图，不能为放大猫而挤走标题。

主标题视觉权重大于logo里的品牌字。风格按菜品与影片确定；保持真实毛发、温暖环境和美食质感，避免把两只真实主角也变成logo里的卡通猫。

### 延展成9:16

用图像编辑/扩图能力，将整张3:4核心等比例居中放入9:16画面，上下只延展厨房、枝叶、木桌等环境，不再重新排版核心。核心内的logo在整幅图中自然位于中间偏上。

对于1080×1920：中央核心为x=0…1080、y=240…1680；上下各240像素只做自然延展。不得在新增的顶部/底部放logo、关键脸、标题或其他核心信息，不画边框、安全区线、面板或硬接缝。

其他画幅按实际尺寸计算。用户明确要16:9时读取现行封面skill的横版规则，以同样的3:4核心向左右延展；不要自动额外制作第二个比例。

## 验收必须看实际裁图

1. 检查真实图像尺寸。仅极小像素偏差且边缘无关键内容时，可微裁到正确比例再等比缩放；不能拉伸猫脸或通过大裁剪补救失败构图。
2. 从最终完整封面裁中央3:4：q=floor(min(W/3,H/4))，取3q×4q居中裁切。1080×1920对应1080×1440，边界y=240…1680。
3. 查看完整图、真实裁切图、390像素宽的两张手机预览。标题、logo完整字样、猫耳与脸、核心菜品及文字阴影都应保留，并有余量。
4. 逐字核对菜名与“喵掌勺”，检查复制脸、额外肢体、logo黑底、场景接缝和背景抢字。
5. 裁切失败时修构图后重新检查；不能只报告“已按安全区生成”。

可运行：

```sh
python3 scripts/crop_cover.py /absolute/path/封面-9x16.png /absolute/path/封面裁切检查
```

输出目录应为新目录，避免覆盖已有文件。脚本需要Pillow；若当前Python缺少它，优先使用本机已有的图像处理运行时，不全局安装新依赖。可用`python3 scripts/test_crop_cover.py`检查裁切几何、像素保留和拒绝覆盖。该脚本只记录尺寸、裁切和缩略预览，无法判断logo或文字是否完整，仍须查看图片。

使用图像模型整合logo时，不能把外观目检通过写成原始PNG逐像素一致。若任务明确要求像素级原样，按用户明确允许的精确合成方式处理，并单独验证；不要把近似重绘伪称为原资产像素复制。

## 交付

独立封面目录保留：完整指定比例封面、同图实际中央3:4裁切、最终采用的提示词与参考用途、真实尺寸/裁切边界/文字和缩略图检查记录。原稿与未采用版本分开保存，不把失败版冒充完成态。

本地检查不等于平台上传后的裁切/压缩检查。用户只要封面时交付图片，不擅自覆盖视频第一帧、修改已有成片或发布。
