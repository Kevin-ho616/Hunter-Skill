# 喵掌勺

把一道菜做成有完整劳动过程、夸张身体喜剧和共餐回报的双猫短片，再用真实成片制作品牌封面。当前用户要求优先于以下默认。

## 制作默认与范围

- 主角为一只纯白英短和一只纯黑英短，圆脸、短毛、金色或琥珀眼；白猫主事，黑猫嘴馋、好奇、想省事，负责夸张捣乱，也真正出力。没有另行指定时不加衣服、第三只主角、对白、旁白或字幕。
- 气质为照片级乡村美食动作喜剧，9:16竖屏。制作路线从用户要求的取材环节走到成菜、共餐；不擅自跳过用户点名的过程。
- 默认视频模型 MiniMax H3，读取实时契约后使用768P档，最终交付720×1280。本默认已包含生成与交付分辨率的区别。用户指定其他模型、比例或原生清晰度时按其要求核对；不要擅自换成H3 Max或2K。
- **更夸张、更快**：原型常规段8秒、复杂段10秒；新片先试常规6–7秒、复杂完整笑点8–9秒，即同类生成段缩短1–2秒。按动作完整度与当前模型范围调整，不等于只把总片长减少两秒，也不靠全片强制加速实现。
- 只要求拆解、策划、封面或局部修改时，只完成所要部分。要求完整视频时持续推进到可播放成片与封面；用户已有明确制作授权，不反复询问常规实现选择。

## 1. 从实际素材与菜谱动作开始

读取用户素材、既有项目和已批准内容。新任务一句话说明采用的画幅、角色、模型和约略长度；缺失但可合理推断的常规选择直接推进。

先列食物状态链和关键操作，再放笑点。例如黄豆应经过剥荚、淘洗浸泡、磨浆、过滤煮浆、点卤、压制，才成为可切块的豆腐。食材辨识、加工先后和可见结果要清楚；虚构喜剧不强制变成菜谱教学。

参考片拆解、角色关系、冲突密度与夸张方法见[喜剧与节奏](references/comedy-and-pacing.md)。需要具体起点时看[麻婆豆腐快节奏示例](references/mapo-example.md)，不要把它当成每道菜必须照抄的情节。

## 2. 把笑点写成可执行的动作段

基本动作链：**当前任务与空间 → 黑猫的欲望或笨办法 → 动作升级 → 可见后果 → 白猫反应 → 工序继续**。

- 一段优先承载一个主要笑点、一项食物进展；夸张黑猫的用力、身体姿态、道具反作用或尴尬表情，别靠不断堆新事件。
- 钩子、冲突、笑点不同。每镜承担推进、铺垫、兑现、反应或食欲展示即可，不要求每镜冲突或每段拍头。
- 为黑猫保留贡献、成功和最终吃到成品的回报；白猫有熟练操作、接手、制止与照应，不能只剩处罚。
- 关键道具在出事前入画。弄湿、弄脏、少掉一块等后果在后镜承接，不能无缘无故复原。

分镜至少写：段号、工序、输入食物状态、允许到达的输出状态、黑猫企图、主要动作与后果、白猫反应、景别/空间、拟音、**生成秒数、预计剪辑秒数**。时间在生成前标为估计，按实际产物回读后更新。

## 3. 在 LibTV 中建立可回读的制作链

按[LibTV制作与恢复](references/libtv-production.md)执行；工具名称、参数、默认值和运行准入以当次发现与实时契约为准。

1. `doctor`确认连接，明确项目并用精确ID绑定；复用合适项目，只有需要新片时新建。
2. 先把完整分镜和角色约束落到可读回的画布实体，保存宿主侧的节点、任务、提示词、来源与稳定幂等键。
3. 查询合适图片模型，生成角色主参考、场景参考及各段首帧；每项只做需要的一份，不自动加变体。
4. **先实际查看首帧，再决定生成视频。** 查看工具返回后完成判断，不能在尚未看到像素的同一编排调用中紧接着付费生成。核对猫身份、食材、道具位置和出事前状态。
5. 查询并读取视频模型契约。H3优先用已验收的单首帧节点生成；参考编号和媒体列表交给工具，不自行拼接。保留原任务身份查询、恢复，接受回执不等于完成。
6. 逐段看真实产物、校准镜头边界，必要时只修正失败的部分。尽量先通过裁掉错误尾部解决，不盲目整片重拍。

**每段提示词只讲当前工序。** 写清这一段开始时食物是什么、做什么、结束应是什么；不要把整条“豆浆→豆花→豆腐→炒菜”塞进每段提示词，否则可能提前出现后续状态。未来状态的限制保持简短，主体叙述仍聚焦当前动作。

## 4. 剪辑、声音与交付

- 生成时已经缩短1–2秒；剪辑再去掉开头呆站、动作完成后的重复表情和错误变形。保留起因、接触、后果与短反应，不截掉笑点兑现。
- 菜品/工序近景、正常劳动与笑点交替；使用动作、道具或声音衔接。不要用频繁转场遮掩因果断裂。
- 保留可用现场声和动作拟音，配轻快器乐；不把更搞笑理解为音量更大。用实际音频长度对齐，不能把“生成成功”当作已经听过。
- 优先用LibTV合成。遇到音频时长缺失或原生导出绑定问题，按恢复文档使用已获交付许可的素材在本地剪辑/混音，记录真实流程，最终成片再回传同一项目。
- 转为720×1280时保持主体比例，按内容小幅裁边或留边，不拉伸猫脸。保存完整解码、分辨率、帧率、时长、音轨与画面检查证据；区分技术检查、完整试听、手机观看和平台转码。
- 回传必须经过实际文件字节上传、审核和画布挂载；回读节点真实媒体绑定，再展示成片播放卡。保留本地文件和可重建来源。

## 5. 视频完成后做喵掌勺封面

读取现有[视频封面设计skill](/Users/kevin/.codex/skills/video-cover-design/SKILL.md)，再按[品牌封面流程](references/cover-production.md)制作。默认只做视频当前比例。

- 从真实成片选能说明双猫与菜品的关键帧，用内置图像生成工具制作；标题默认只用菜名。
- 默认使用随skill保存的[喵掌勺透明logo](assets/miao-zhang-shao-logo.png)，放在**中央3:4核心内的中间偏上位置**。保留品牌文字和图形；用户当次提供新版时以新版为准。
- **先排好完整3:4核心，再扩展到9:16。** 核心包含完整logo、猫耳与脸、主要菜品和全部标题及描边阴影；上下只延展环境。不要把logo排在全图顶部、标题排在全图底部。
- 从最终完整封面真正裁出中央3:4，查看大图与390像素宽缩略图。任一关键信息被切掉就继续改，不能凭提示词或尺寸检查宣称通过。
- [裁切检查脚本](scripts/crop_cover.py)只做实际裁切、缩略图与尺寸记录，不负责设计，也不能代替视觉判断。

## 交付与后续试片

交付实际可播放视频、LibTV精确项目/节点、本地文件、分镜与任务记录，以及完整封面、实际3:4裁切、封面提示词和检查记录。播放器已展示时遵循结果卡约定，不重复堆放相同媒体。

本skill的“更夸张、单段缩短1–2秒”是用户指定的后续制作默认，尚需新片实测。试片优先看：黑猫的企图是否一眼可读、后果是否够明显、快节奏是否仍能看懂、工序是否提前跳变、封面实际裁切是否完整；据真实反馈局部调整，不把一次偶发输出扩成万能规则。
