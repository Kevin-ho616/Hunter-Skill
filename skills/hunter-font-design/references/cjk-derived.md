# 中文标题字：开源骨架定制与覆盖核验

用于用户已选择简中标题字实用整库路线时。已有的三案选样、真实控制字、源轮廓网格和封装流程继续适用。本参考不提供逐字原创中文的自动完成承诺，也不代替其他文字、竖排、可变字体或复杂塑形验证。

## 先确定制作路线与字符范围

- 区分逐字原创与允许修改的开源骨架定制，说明来源及工作量差异，由用户选择。已有明确选择不重复询问。选开源路线不等于选某种字形；选样流程仍要完成。
- 定制路线先核验官方原字体与许可，保留原件、内部版本、固定提交或发布版本、下载 URL 和哈希。遵守衍生许可、保留名称及归属要求；重新命名，不把数千个继承骨架的汉字称为逐字原创或独占字库。
- 约定具体汉字、英文、数字和标点清单。“完整中文”没有默认的整个 Unicode 范围。若约定 GB2312 汉字，按有效编码生成并核对 6763 个唯一汉字；额外符号另列，不能由 OS/2 代码页位或能显示就推断 GB18030、繁体整库或生僻人名已覆盖。

## 真实控制字与结构保护

- 从独体、左右、上下、包围/半包围和密集结构选字；可选永中木水、口日月国田回，以及题量意海赢警密等，具体按本项目与源字体安排。加上真正要使用的英文、数字和中文标点。
- 先出真实小字集试验字体与同尺度源网格，再看实际标题尺寸、小一档和反白。汉字的 em、字面框与占位不同，不能逐字把包围盒拉满或用浏览器横向缩放冒充新字体轮廓。
- 横向比例变化须同时处理源轮廓、占位、边距和必要的英文间距。加厚、削角后对照独立组件、字腔数量/面积和最窄通道；自动处理损坏关键结构时，降低幅度或保留该字原细节，并记录例外。拓扑数量没变不能证明开口仍清楚或字形已好看。
- 切角只作用于符合设计规则的外角；短笔画、内凹角、曲线、钩、点和撇捺不能机械套同一处理。方向加厚的离散平移并集可能在曲线/斜线相交处留下毛刺，须先在真实控制字的大图和目标字号中验证边缘，再扩到整库；具体几何算法与幅度属于项目实现。
- 保存控制字基线；扩字后比较原控制字的轮廓、占位与修形数据，排除扩字意外改回母字。

## 整库与导出检查

1. 对全部约定码点查 cmap、唯一性、非预期空白和 `.notdef`；单独验证空格、不换行空格与全角空格等预期空字形。
2. 检查实际 TTF/CFF OTF 的闭合轮廓、有限坐标、度量、行盒和转换误差；网页容器从同版桌面字体派生，解包比较覆盖、轮廓、占位与所需布局。
3. 用真实塑形引擎跑全部约定汉字及连续中文、中英数字标点混排，确认没有缺字。用实际字体逐码点栅格化并提供分页校样；这两步分别检查编码/导出与可见字形，不相互代替。
4. 所声称支持的格式分别在浏览器实际加载，核对下载字节哈希，测量中文控制字的真实字面与占位。通用试排页的拉丁检查之外，另验中文默认文字、预设、密集字和网格。
5. 逐页扫描全字符校样，并记录视觉检查的层级；自动栅格化或模型扫描不冒充专业设计师的逐字正式审美验收。行距、标点位置和长标题节奏需实际试排。
6. 保留可编辑源与可重建入口，必要时从固定上游在干净目录重建并比较字体字节。按既有封装要求解压、回读、验证清单和随包试排页。

## 验证边界

此路线已在一个基于开源黑体骨架的简中横排标题字项目中完成工程、全字集栅格、真实塑形、三种导出格式的本机 Chrome 加载及 macOS 进程内注册验证。具体覆盖、字重、字宽、切角幅度和字腔阈值不作为后续项目默认参数。

没有因此验证逐字原创中文、所有其他骨架或格式，也没有验证 Windows/Adobe/Office、系统安装、手机真实设备、印刷及正式发行。平台能力、命名/许可、工程通过与审美确认仍分别报告。
