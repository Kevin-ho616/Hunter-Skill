# 中文扩字与风格迁移

用于把风格方向、少量中文手稿或已确认的西文字体延展为一套中文字体。新设计先按主流程选样。已有认可母版时，在母版上提取可验证的规则。

## 从用字场景选择路线和字集

| 路线 | 适合 | 保留的源与证据 |
| --- | --- | --- |
| 原创部件 | 需要独立骨架、书写逻辑或强风格的标题字 | 真实控制字、可编辑笔形和部件、位置配方、单字例外。每个派生字都能追到母部件 |
| 开源骨架定制 | 已有允许改造且地区字形合适的字库，近期需要数千字可排 | 固定上游和许可、逐字应用规则及例外、可重建工程。按[中文衍生流程](cjk-derived.md)核对归属、输出和覆盖 |
| 混合制作 | 需要重点字的原创特征，也要在约定范围内先有实用覆盖 | 逐字记录原创、改造、原样沿用或待制。小批测试先比较两类字在同一句标题里的风格断层 |

确定实际文字、地区字形、字号和排版方向。先做项目必用字与跨结构控制字，再对选定字表分批扩展。简中可以指定《通用规范汉字表》一级 3500 字、一级加二级 6500 字或主表 8105 字；约定 GB2312 时独立核对其 6763 个汉字清单。分别列出拉丁、数字、全半角标点和增补姓名地名。逐码点写入项目 `font-targets.json`，公布所用字表依据。若要求简繁、多地区或 GB18030，明确各自版本、级别、码点与语言样本。用[教育部字表说明](https://www.moe.gov.cn/jyb_xwfb/xw_fbh/moe_2069/s7135/s7562/s7565/201308/t20130829_156533.html)确定《通用规范汉字表》的分级范围。

## 把风格写成能跨字复用的规则

先用真实轮廓量出风格的识别点，写到[设计规则表](../assets/design-rules-template.md)。记录适用结构、测量位置、可变幅度和保护条件。数值从本项目控制字和实际字号确定。

| 要延展的特征 | 中文里的实现 | 控制字与压力样本 |
| --- | --- | --- |
| 西文笔画对比与端头 | 确定横、竖、斜笔的视觉笔重；分别设计撇、捺、点、钩和折。平切、楔形或圆头选在可见的笔段端部 | 一十永大小，知和 |
| 西文方角或削角 | 选择有足够长度的外凸转折。根据笔段和字号缩小削角，保全内角和连接 | 口日田国、器、警 |
| 窄长、厚重或宽扁 | 定一个中文占位与字面体系，再调整中宫、重心和部件空隙。疏字避免零散，密字为通道留白 | 中山人、意量、赢藏 |
| 一组笔形在不同位置的节奏 | 为同一部件画独体、左窄、右宽、上扁、下部与包围内变体。比较端头、主笔宽和避让 | 木林森、杏呆困、休相村 |

用相同 em 的源网格加实际字号、低一档字号和反白审样。混排同时检查汉字、中西标点、拉丁大写和数字的黑度、视觉基线、字面宽及节奏。对未见过的字形，不从拉丁字母形状直接拼汉字；按汉字的字形规范重构对应笔形。

### 少量参考先量局部再试扩字

- 把参考字分为笔画本体、接合、外端、部件间留白和内部字腔。逐条保存原图或轮廓坐标、所处结构和观察区间。斜笔的粗细取法向截面，端头记录切向与伸缩方向；同时量横间距、交叠区域和字腔窄处。对同类笔画多处取值，将读到的关系与单次测值分开。可用[参考局部探针](measurement-and-targets.md#少量汉字参考的局部取样)回读像素证据。
- 将规则写成适用条件。比如同一横笔在开放端、接竖、封闭轮廓上可有不同收法；同一部件换到左侧、下方或框内，优先保护标志性轴向、转折和空白形状，再调整笔重、长度和相对位置。对笔画方向相反或显著疏密不同的样本保留各自角色。只测了一处的外角或笔宽，先验证同构字，勿提升为整库常量。
- 区分直接观察、在新结构中的推导、参考缺项。原图没有的框、钩、密集结构或地区造型列为候选，单独交代构造依据。不要为让风格统一而复制某个斜角、轮廓或白缝到没有同类约束的部位。
- 先做同一部件换位置和无同部件但结构类似的小组。新字与母字用同 em、同墨色、等比例放大及目标字号同排，另做小一档，比较重心、出锋、折角和内白随高度的变化。修订时也把旧版按相同条件并排。轮廓拟合、字腔和编译通过只能说明各自检查结果；风格证据不足的组保留试推状态，审校到位再扩大字符量。

## 建部件库、构形表和留出字

1. **控制字先行。** 覆盖独体、左右、左中右、上下、上中下、全包围、半包围和嵌套。加上密集交叉、曲折、钩和长斜笔。控制字既看常用程度，也看能覆盖多少不同构形与笔形；具体数量随项目决定。
2. **把复用拆到合适的层级。** 用稳定的部件名记录原形、适用位置、主笔宽、边界和允许变体。以木为例，`木`的捺、`林`的左木及`困`的框内木需要不同的避让。优先按语境重新安排笔路和粗细；可用 UFO 部件，或用支持相容层的[Glyphs 智能部件](https://handbook.glyphsapp.com/components/smart/)管理宽、高和端头变化。反查所有直接和间接依赖。
3. **把整批目标字摊开。** 先按构形、部件位置、密度和频率归组。表中每字记录码点、地区、构形、部件版本、位置配方或单字源、处理状态及异常。允许用有版本和授权的 IDS 数据预分组。IDS 描述部件关系，位置坐标、重叠、比例与地区造型由本字库的轮廓和校对决定。未知分解或规格冲突标为人工处理。参见 [Unicode 第 18.2 节](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-18/)。
4. **先验外推，再加量。** 在定规则前另留一组未参与定参的字，选见过的部件出现在新位置、陌生组合和复杂结构的例子。冻结当前规则后组装留出字，再看结构、笔宽、内白、字面及目标字号。失败时将原因落到部件变体、布局规则或单字例外；规则改完重新抽取留出组，并复核已认可母字。切勿把单字修好、已有编码或能显示当作全组合格。
5. **分批扩大。** 首批整句能阅读后，按可复用部件和高频字推进，优先做能检验规则的密集组。对仅局部风格化的批次保留逐字记录。对单字手改，先判断是共用规则还是该字例外；在可重建源中登记并重编受影响的字，不从已经摊平的导出逆推父部件。

## 用实际组件生成一批可编辑草稿

`scripts/assemble_cjk.py` 使用单母版 UFO 中的真实部件。先在 UFO 绘制各位置的变体，再在构形配方里填写部件名与平移坐标。下例假设 `part.wood.left` 和 `part.wood.right` 已在母版里绘好，且项目字表包含“林”。数字用本项目 UPM，示例坐标仅供演示。

```json
{
  "advance": 1000,
  "glyphs": {
    "林": [["part.wood.left", 96, 80], ["part.wood.right", 524, 80]]
  }
}
```

```bash
python /absolute/path/to/hunter-font-design/scripts/assemble_cjk.py \
  parts.ufo layout.json new-batch --targets font-targets.json
python /absolute/path/to/hunter-font-design/scripts/check_source.py new-batch/draft.ufo \
  --out new-batch/source-check.json
python -m fontmake -u new-batch/draft.ufo -o ttf --output-path new-batch/draft.ttf \
  --validate-ufo --overlaps-backend pathops
```

草稿保留部件引用，沿用源字体的 UPM，并按配方设定统一占位。脚本只执行明确配方的平移，笔宽变化在部件源中处理。它拒绝已有字形覆盖、缺少部件、循环、无可见轮廓及不在项目字表内的配方。缺字按码点写入 `layout-report.json`，完成后继续用真实字体核对意外空白。以批次覆盖的 `font-targets.json` 验收阶段字体，正式交付时换回约定的全量字表验证。该工具可用于原创或混合路线的部件装配。底字许可、复杂上下文、参数化笔形和单字光学校正按项目实现。

## 用全库验收区分「已覆盖」和「风格成立」

- **结构与字形身份。** 用 `check_source.py` 追踪部件并检查闭合、部件缺失或循环。检查形近字如未/末、己/已/巳、土/士及复杂上下部。包围和嵌套分别检查内白、最窄通道、上下接缝和错误粘连。开源规则检查每字应用状态；截面厚度异常、字腔变化、裁切、合并、碰撞或部件位置偏差时降低处理幅度或转人工，记录原因。子形变更后按依赖回归。
- **编码与真实渲染。** 全字表跑 `check_font.py` 及真实塑形，无 `.notdef`、无意外空白。登记导出哈希，生成当前字体的分页校样，逐页查错笔、内白、字形身份和排版节奏。对高风险组再看实用字号、小一档和反白。GB 对照看逐码点覆盖与实际字形，避免只查字体声明。
- **地区与语言。** 简体、繁体与地区字形的字符收集和轮廓选择分别审校。若以同一字体提供地区字形，用相应的 `locl` 替换和真实语言标签验证；涉及竖排另测 `vert`/`vrt2` 及标点。参见 [OpenType Localized Forms](https://learn.microsoft.com/en-us/typography/opentype/spec/features_ko#tag-locl)和[专项验证](specialist-workflows.md)。
- **模型候选（按需）。** 少样本生成可给复杂组合提供候选轮廓参考，使用有授权的训练素材和字形内容。候选仍须核对结构、可读性、笔画身份和内白，再回源矢量化、记录部件和编译审校。现有研究表明局部特征及部件间空隙都会影响字体风格，不能把一个全局效果当作批量可用字形。参见 [XMP-Font 原论文](https://openaccess.thecvf.com/content/CVPR2022/html/Liu_XMP-Font_Self-Supervised_Cross-Modality_Pre-Training_for_Few-Shot_Font_Generation_CVPR_2022_paper.html)。
