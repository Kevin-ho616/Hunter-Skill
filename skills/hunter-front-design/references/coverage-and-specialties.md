# 覆盖范围与按需专项

用于判断“本项目完整”需要做什么，不把所有字体门类自动加入每次委托。主流程继续使用 SKILL.md 的需求、研究、选样、控制字、扩字、光学审校、工程、交付与维护；本页补充触发条件和需额外取得的证据。

## 先确认完整性的范围

- 记录字体用途/类别、明确字符与语言、字重/字宽/斜体或轴实例、目标尺寸、横竖排、桌面/网页格式、所需功能和目标应用。专业符号、图标或仅有字标的任务另定语义与覆盖，不假定它们都是完整文本字库。
- 在[项目规则表](../assets/design-rules-template.md)列出每个适用项、检查方式与完成证据。适用项可记已检/有问题/未检；只有委托确实不需要时才记不适用。所需能力缺工具、缺语料或缺语言审阅时保留待补状态，继续独立可做的工作，不能用“不适用”掩盖缺口。
- 区分：已有操作与工具、可沿用主流程但需专门实现/审阅、现有工具未覆盖。现有脚本负责测量、声明范围内的静态字体工程检查、离线试排和技术册，并不是通用自动造字器、完整格式认证或所有文字的专业审校引擎。
- 完成以本项目必需证据为准：设计/光学、字体结构、语言与塑形、用户确认、目标平台和封装分别记录。所需专项未完成时，不以某个脚本的 PASS 宣称全项目或正式发行验收通过。

## 按任务触发，不按固定数量凑检查

| 任务/触发条件 | 增加的设计与验收事项 | 当前能力边界与转入路径 |
| --- | --- | --- |
| 衬线、强笔画对比、书写/装饰造型 | 先确定衬线与接合、笔画对比、端头、书写方向或装饰层级；按真实结构选择母字，复查小尺寸细节、悬出与识别，不套用已验证无衬线字体的几何参数 | 沿[结构审校](design-review.md)建立项目规则；没有覆盖各风格的预制字形生成器 |
| 多字重、多字宽及斜体/倾斜体家族 | 先定成员、共同骨架、视觉重量梯度、字符/功能一致性与行距关系；需要插值时先检验母版兼容及中间实例。斜体/倾斜体明确造型路线，复查曲线、端头、悬出、附标和字距；核对家族分组、样式链接与实际粗斜体选择 | [命名流程](bilingual-naming.md)提供部分工程规则；不把自动加粗、横向压缩或机械倾斜当成家族已审。插值原则见 [Glyphs](https://handbook.glyphsapp.com/interpolation/) |
| 正文、界面或低像素尺寸 | 用实际段落、行长、字间/词间与多行标点判断阅读节奏、灰度、开口及易混字符；按目标屏幕、缩放、字号和栅格环境检查。按用途评估 hinting 与光学尺寸，比较处理前后，提示不能修复错误骨架 | 现有字号阶梯仅作部分证据；未提供专用 hinting 引擎，也未替代真实设备/阅读审阅。参考 [Glyphs Hinting](https://handbook.glyphsapp.com/postscript-hinting/) |
| 拉丁扩展、希腊/西里尔或多语言覆盖 | 逐语言列码点与真实词句，核对本地造型、大小写、附标、NFC/NFD、所需 locl/mark/mkmk 等；记录实际语言、脚本、方向和特性条件。字符存在与能排对该语言分开判断 | 普通 cmap/样本检查只覆盖一部分；共享 shape 帮助函数不提供完整的语言/方向/簇审阅接口，必要时增加专门 HarfBuzz 测例与语言审阅。见 [OpenType 标准文字](https://learn.microsoft.com/en-us/typography/script-development/standard) |
| 逐字原创中文或扩展到其他地区字形 | 明确地域/语言与字集依据，建立笔画、部件、重心、中宫、字面疏密及跨结构组规则；逐组扩展与校对，检查错字/地区异体，不以骨架加厚/压窄冒充逐字原创 | 现有[中文参考](cjk-derived.md)主要是开源骨架定制；原创整库需额外的造字与语言审校，不承诺自动完成 |
| 中文/日文等竖排、混排或版面专项 | 增加相应垂直度量、竖排替换、直立/旋转、标点括号、横排数字及跨文字基线/行盒；检验所约定的禁则、挤压与排版引擎行为，区分字体与应用负责的事项 | 横排网格和通用浏览器检查不证明竖排通过；依据目标文字规范与引擎另测，如 [中文排版需求](https://www.w3.org/TR/clreq/) |
| 阿拉伯、印度文字、泰文等复杂塑形 | 使用对应脚本的真实字素/词句，检查所需替换与定位、连接/重排、附标叠放、簇、方向及断词上下文；用相应语言/脚本参数和专业审阅确认结果，不能逐码点插距或只查无 .notdef | 通用 shape 解析不等于文字规则已实现；需专门的布局规则、语料和引擎比较。按文字查 [OpenType 脚本开发](https://learn.microsoft.com/en-us/typography/script-development/arabic) |
| 可变字体 | 规划轴范围/默认值/映射、母版兼容、命名实例与 fvar/STAT 等所需数据；在轴端、必要中间态及多轴组合检查轮廓、度量、字偶、附标和所需特性，核对静态实例与目标应用 | 当前工具仅检查默认实例；不能以默认实例 PASS 代表轴空间。另建可变构建与验证，见 [OpenType Variations](https://learn.microsoft.com/en-us/typography/opentype/spec/otvaroverview) |
| 彩色字体、emoji 或位图字 | 明确目标格式与客户端版本，检验图层/调色板、透明混合、缩放与回退；涉及 emoji 时另验所需变体选择符、ZWJ 等实际序列。格式由需求决定，不默认同时生产全部彩色格式 | 常规轮廓边界/字板不覆盖这些机制；需对应格式的导出与实际渲染，例如 [COLR/CPAL](https://learn.microsoft.com/en-us/typography/opentype/spec/colr) |
| 等宽/代码字体、图标或专业符号 | 等宽任务核对全部承诺占位、组合符号和真实代码场景；图标/符号明确编码、语义、尺寸与替代机制。专业公式还需数学布局数据、伸缩构件与实际公式，不以几个运算符冒称数学字体 | 普通度量只覆盖部分；数学项目另按 [MATH](https://learn.microsoft.com/en-us/typography/opentype/spec/math) 和目标公式引擎执行。音乐排谱等其他专用字库同样另建对应规范/样本，不套用拉丁标题字验收 |
| 网页子集、语言拆分或体积优化 | 明确完整/子集交付、码点和功能范围，保留所需替换字/附标等依赖及许可信息；核对实际缺字/回退、塑形、文件体积与加载。网页部署在范围内时另测 CSS、MIME/CORS、缓存和字体切换布局 | 完整容器等价检查不能验收删字后的子集；用 [FontTools subset](https://fonttools.readthedocs.io/en/latest/subset/index.html) 等实际工具按当前参数验证，不能为省体积悄悄删掉承诺功能 |
| 正式生产与目标平台发行 | 按轮廓类型检查节点/方向/闭合、重复与自交/重叠、部件、极值、提示和表结构；选与目标相符的检查 profile，解释每个警告；实测所承诺的安装/更新、家族菜单、应用排版、PDF 嵌入或印刷 | 通用脚本不做完整合规/几何审计；按需使用 [FontBakery](https://fontbakery.readthedocs.io/en/stable/fontbakery/profiles/universal.html)、OTS 或编辑器工具，并保留真实版本/结果。不能默认套用某个平台的全部发行要求 |

本页给出专项的识别与最低证据要求，不声称已实现这些领域的全部编辑、自动检查或专业设计能力。所需表、功能、许可和平台规则以项目采用的当前规范及实际工具为准。

## 交付后继续有效

按[版本维护、源与旧文件](engineering-packaging.md#版本维护源与旧文件)维护权威源、构建入口、变更记录与同版副本；清理和卸载遵守用户已有授权。不要让旧 source、旧网页字体、历史海报或其他项目依赖在下一轮悄悄覆盖当前版本。
